# Repository instructions

- Use Bun for installation, scripts, and tests.
- Never add real customer, project, employee, bid, CRM, or credential data.
- Benchmark fixtures must be synthetic, licensed, or explicitly approved for
  repository use.
- A construction skill must cite source locations, expose uncertainty, and
  preserve human approval at contractual, safety, cost, or schedule decisions.
- Add or update a benchmark whenever behavior changes.
- Run **bun run check** before committing.


- Keep both plugin manifests and package.json versions synchronized.
- Keep deployment schedules, tenant configuration, and customer mappings downstream.
- Document platform support honestly; package validation is not a runtime smoke test.
